Pack intake checklist

Keep tariff rules + data packs complete and current. Completeness is a source / pack / golden problem — not an LLM-depth problem. Use this form for any new or amended CSMS, Federal Register annex, proclamation, or broker dispute that touches Chapter 99 / HTS lists.

Related: program_watch.json program_status.json OPEN_ITEMS.md RULES

Gate: when a pack may exist

A pack is allowed only when authority names all three. Investigations without a proclamation / FR annex / CSMS → PENDING in program_watch. Do not invent headings.

Broker dispute intake (highest-signal QA)

When a licensed broker or compliance reviewer disagrees with the tool — capture, then route to: golden → pack fix or invent fix → RULES example → close OPEN item.

LLM / agent use (optional)

Do use models to:
  • Diff an attached CSMS HTS list against pack JSON
  • Draft goldens from a filled intake + authority PDF/text
  • Explain assess output vs expected stack (pack gap vs invent bug)
Do not ask models:
  • “Are we complete for Section 232?” without the attachment
  • To invent Chapter 99 headings or HTS membership from memory

Required prompt pattern: attach primary document + current pack; require heading + HTS stem + effective date; if not in attachment → OUT OF SCOPE.
