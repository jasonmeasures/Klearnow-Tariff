Audit an entry

Compare what was filed against what the rules require.

The audit runs on the lines already in the calculator, so there is one set of inputs rather than two. On each line, open + and enter the Chapter 99 codes as filed. Set as known on to the filing date so the entry is judged against the rules in force then, not today's.

What the audit checks
Missing codeA heading the rules require that was not filed, with its duty impact. Includes affirmative $0 reporting lines, which are commonly omitted and cause a transmit rejection.
Over‑applicationA code that was filed but is suppressed by an exemption — an overpayment.
List differenceA Section 301 list code that differs from the expected one. Reported as information, not an error: the lists are mutually exclusive and membership is HTS‑specific, so it needs an annex check rather than a correction.
ReconciliationFiled duty total against computed, to the cent.

API & reference

Integrate other tools, connect Claude via MCP, and review the CBP mechanics the engine implements.

Integrate

The rules engine is the API. Auth with X-API-Key (local default dev-internal).

  • GET /v1/hts/{code} — baseline Column-1 rate
  • POST /v1/hts:coverage — which rules apply to an HTS list (no value)
  • POST /v1/entries:assess — duty stack (engine=auto|ch99)
  • GET /v1/rules — browse live rules
  • PUT /v1/admin/s301fl/countries/{iso2} — hot-update 301-FL (no rebuild)
  • GET /v1/openapi.json — machine-readable contract

MCP for Claude / Cursor: run cd mcp && npm i && npm start with the API up, then point the client at that stdio server (see mcp/README.md). AI can assess and upsert 301-FL rows without a frontend rebuild.
